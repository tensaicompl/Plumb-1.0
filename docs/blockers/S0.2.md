## Exact blocking fact

The S0.2 contract requires two things that cannot both hold for the read-only HR fixture:

1. **List classification is structural only.** A non-heading paragraph is `ListItem` only when its effective paragraph properties contain `w:numPr`, directly or through its style chain; no textual marker is fabricated or interpreted, and there is no inference from text (S0.2 steps "Paragraph classification" and "Extracted-text records"; Hotfix 021 §§27, 52).
2. **HR acceptance requires `ListItem`.** Every fragment of `fixtures/hr-leave/requirements.docx` containing one of `HR-001`..`HR-032` must be `FragmentKind::ListItem` (S0.2 test step; Hotfix 021 §50).

The fixture contains no list numbering at all. Its package has only `[Content_Types].xml`, `_rels/.rels` and `word/document.xml` (no `word/styles.xml`, no `word/numbering.xml`), and `word/document.xml` contains no `w:numPr` and no `w:outlineLvl`. Each requirement is an ordinary paragraph whose run text itself starts with a literal number, for example:

```xml
<w:p><w:r><w:t>1. HR-001 [functional] The system shall allow an employee to create a draft leave request.</w:t></w:r></w:p>
```

So under rule 1 all 32 requirement paragraphs are `Paragraph`, and rule 2 fails. Hotfix 021 §52 assumed the numbers were Word numbering presentation absent from `w:t`; in this fixture they are literal `w:t` text.

Everything else in the S0.2 contract was implemented and verified before stopping (see below); this is the only failing requirement.

## Resolution

Resolved by human-approved Plan Hotfix 022.

Resolution: the fixture-specific acceptance was wrong. HR-001..HR-032 in `fixtures/hr-leave/requirements.docx` are `Paragraph` fragments because their ordinals are literal `w:t` text and no effective `w:numPr` exists. DOCX list classification remains structural only: a paragraph is a `ListItem` only through direct or style-inherited `w:numPr`, never through literal numbers, bullets or punctuation in its text.

The fixture remains unchanged. S0.2 returns from `blocked` to `pending`.
