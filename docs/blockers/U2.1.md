## Blocking category

- `BLOCKED-SPEC-MISSING`

U2.1 requires pre-commit semantic-diff previews, but the authoritative API/specification pack defines no operation that can supply them. The missing item is specification/contract material, not an implementation choice.

## Exact blocking fact

U2.1 lacks a server-authoritative pre-commit semantic-change preview contract for both of its governed diff-preview workflows:

- **Glossary merge.** The v3 U2.1 task requires "Glossary merge displays resulting semantic diff before commit", with the acceptance "glossary merge requires diff confirmation". This inherits v2 §8 U3 "Glossary [P] list, conflicts with pick/merge".
- **Requirement split.** U2.1 required action 1 inherits v2 §8 U2 "actions reclassify/waive/split (diff preview)/mark-duplicate".

Current runtime and contract facts:

1. **Glossary merge.** `POST /api/glossary/{id}/merge` (`merge_glossary`) takes `If-Match` and `GlossaryMergeRequest { into, reason }` and returns `WriteResult`. The handler (`crates/plumb-api/src/routes/model.rs` `merge_glossary`) builds the server term-merge Proposal with `plumb_functional::vocabulary::propose_term_merge` and then calls `state.write(…, "merge_glossary")`. That is `ApiState::write` (`crates/plumb-api/src/state.rs`), the shared governed write path: X1.3 intake then CAS commit. It commits immediately. There is no pre-commit semantic diff response.
2. **Requirement split.** `POST /api/requirements/{id}/split` (`split_requirement`) takes `If-Match` and `SplitRequest { parts, reason }` and returns `WriteResult`. The handler (`crates/plumb-api/src/routes/requirements.rs` `split_requirement`) calls `propose_requirement_split(…)` and then `state.write(…, "split_requirement")`, committing immediately. There is no pre-commit semantic diff response.
3. **Model diff.** `GET /api/model/diff` (`get_model_diff`) takes optional `from`/`to` **existing revision IDs** (`to` defaults to head, `from` to the parent of `to`) and returns `ModelDiff`. It compares stored revisions, so it cannot describe a candidate that has not been committed. It is the only operation in `api/modeller.openapi.json` that returns `ModelDiff`.
4. **Generic intake.** `POST /api/proposals/intake` (`intake_proposal`) requires the caller to supply the complete typed `Proposal` JSON (`IntakeRequest { kind, payload, evidence }`). The UI is not authorized to construct the semantic Term-merge or Requirement-split Proposal itself. The operation persists a pending proposal and returns `IntakeResponse` / `IntakeReportView`, which does not supply the required semantic element diff.
5. The only `patch_preview` in the contract is `AnswerResponse.patch_preview` (`POST /api/questions/{id}/answer`), which is unrelated to merge or split.

Therefore:

- **Commit then fetch the diff** (direct merge or split followed by `GET /api/model/diff`) violates the required order: request → server semantic diff → display → explicit confirmation → commit.
- **A client-computed diff or client-built Proposal** violates CLAUDE.md "Never invent …" and plan §16. The semantic effects of `propose_term_merge` and `propose_requirement_split` belong to the backend; `DiffViewer` only presents a supplied server diff.
- **Out of reach for U2.1.** Its write allowlist contains only UI feature files, `ui/src/app/router.tsx` and the i18n catalogues. It cannot add or change the required capability in `api/modeller.openapi.json`, `ui/src/api/schema.d.ts` or `crates/plumb-api/*`.
